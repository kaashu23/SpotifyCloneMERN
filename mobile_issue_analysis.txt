MOBILE VS. DESKTOP: AUTHENTICATION & UI ISSUES ANALYSIS
======================================================

1. THE "GHOST" COOKIE PROBLEM (CROSS-SITE TRACKING)
---------------------------------------------------
- THE ISSUE: Mobile browsers (Safari on iOS, Chrome on Android) have very strict "Intelligent Tracking Prevention" (ITP).
- WHY NOT ON DESKTOP?: Desktop browsers are more lenient with cookies. Mobile browsers treat your Backend (Render) and Frontend (Netlify) as two separate "strangers."
- THE FIX: We had to use `sameSite: 'none'` and `secure: true`. This tells the phone: "Yes, we are separate, but we trust each other."

2. THE "TRUST PROXY" BARRIER
----------------------------
- THE ISSUE: Your backend is on Render. Render uses a "Proxy" to handle traffic.
- THE PROBLEM: Without `app.set('trust proxy', 1)`, the backend doesn't realize it's being accessed over a secure HTTPS connection when a phone calls it.
- THE RESULT: The server refused to send the "Secure" cookie to your phone because it thought the connection was unsafe.

3. THE 401 REDIRECT LOOP (FLICKERING)
-------------------------------------
- THE ISSUE: We had `navigate('/login')` inside every single page (Home, Search, etc.).
- THE PROBLEM: On mobile, network latency is higher. A page would load, try to fetch songs, and if the cookie wasn't "woken up" yet, the backend would send a 401. 
- THE RESULT: The page would instantly kick you to Login (the 1ms flicker).
- THE FIX: Moved authentication to a central "Protected Route" in App.jsx. This "Gatekeeper" waits for the official word from the server before deciding to redirect.

4. THE "BLANK SCREEN" CRASH (STRICT ENGINES)
--------------------------------------------
- THE ISSUE: Missing imports like `Navigate`.
- WHY NOT ON DESKTOP?: Desktop JS engines sometimes have better error recovery or cached versions of libraries. 
- WHY ON PHONE?: Mobile browsers have strict memory management. If an import is missing, the whole JS thread dies, resulting in a blank screen.

5. UNNECESSARY RE-RENDERS
-------------------------
- THE ISSUE: Clicking "Like" or "Play" caused a global state update.
- THE PROBLEM: If `setLoading(true)` is inside a useEffect that triggers on re-renders, the "Spotify..." screen pops up again.
- THE FIX: Initialized `loading` to `true` and only set it to `false` ONCE. This ensures the app stays interactive after the first load.
